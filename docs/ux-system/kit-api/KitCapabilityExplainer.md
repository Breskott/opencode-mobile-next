# KitCapabilityExplainer — API freeze (wave 0)

Unit: `kit-CapabilityExplainer` (wave 1, tier 1f, kind `kit-part`; added by cut review C20, which replaces slice-P7.3). Spec: kit-v2.md §2.2 (`KitStateView.missing`), §2.5 (`KitRow.unavailable`), §3 (discoverability); `docs/ux-system/capabilities.json` (`matrix`, `enableFlows`, `rules`); `capabilities.md` §4. Rules: STATE-12, STATE-13, AUTO-18, KIT-37, ARCH-2, COPY-12, G13.

## Purpose

The one registry that maps a capability id to:

- why it is missing, in words;
- which hosts can do it;
- the id of the flow that turns it on.

It also provides the widgets that say so in place: a dimmed row, a state, or an offer. The app registers a handler for each enable flow at start-up, so the kit imports no screens. With it, a missing capability is explained, and offered where it can be enabled, instead of silently hidden.

## Replaces

- **Map:** no map element directly. It is the lookup behind every `whenMissing` that moves from `hidden` to `explains` or `offers-enable`. K2 §2.2 counts 285 capabilities gated `hidden`, 82 `explains` and 18 `offers-enable`, and G13 allows `hidden` only where no enable flow exists.
- **Code reach (adopted by wave-2 units per C37):**

## Public API

```dart
/// Where a capability can run: the capabilities.json matrix host columns.
enum KitHost {
  thisPhone,   // builtin: OpenCode in the app's own Linux
  termux,      // a Termux-managed server on this phone
  openCode1,   // oc1Computer
  openCode2,   // oc2Computer
  codex,
  paseo,
  demo,
}

/// One registry entry, generated by hand from capabilities.json and kept
/// equal to it by a test (see Tests).
@immutable
class KitCapability {
  const KitCapability({
    required this.id,            // the matrix id, verbatim: "voice.model", "flag:sessionDiff"
    required this.supported,     // hosts with status "supported"
    this.partly = const {},      // hosts with status "partly"
    this.enableFlow,             // a KitEnableFlows id; null = explains only
  });

  final String id;
  final Set<KitHost> supported;
  final Set<KitHost> partly;
  final String? enableFlow;
}

/// The 21 enable-flow ids, one per capabilities.json enableFlows entry.
abstract final class KitEnableFlows {
  static const addServer = 'add-server';                    // server.any → servers-welcome
  static const phoneSetup = 'phone-setup';                  // phone.builtin → phone-setup-start (setup v2)
  static const phoneSetupTermux = 'phone-setup-termux';     // phone.termux → setup v2, host Termux
  static const serverGeneration = 'server-generation';      // server.oc2 → the This phone card's switch
  static const addServerCodex = 'add-server-codex';         // server.codex
  static const addServerPaseo = 'add-server-paseo';         // server.paseo
  static const addToolClaude = 'add-tool-claude';           // claude.local → setup v2 Add tools
  static const modelSignIn = 'model-sign-in';               // model.auth → sign-in at the composer
  static const teamTurnOn = 'team-turn-on';                 // team.on → team intro, setup per server kind
  static const teamHostGuide = 'team-host-guide';           // team.control → run the host front on {computer}
  static const voiceModelSetup = 'voice-model-setup';       // voice.model → voice-model-setup-sheet
  static const mcpAdd = 'mcp-add';                          // mcp.any → mcp-setup (no assistant option: P2 deferred)
  static const projectChoose = 'project-choose';            // project.open → the chooser
  static const projectGitInit = 'project-git-init';         // project.git → at the Git-needing action
  static const allowNotifications = 'allow-notifications';  // perm.notifications
  static const allowBackground = 'allow-background';        // perm.battery
  static const allowCamera = 'allow-camera';                // perm.camera
  static const allowMicrophone = 'allow-microphone';        // perm.mic
  static const tailscaleSetup = 'tailscale-setup';          // network.tailscale
  static const quotaCollectorGuide = 'quota-collector-guide'; // quota.collector
  static const addExternalAgent = 'add-external-agent';     // agent.a2a → Integrations
  static const all = <String>[/* the 21 above */];
}

/// What a handler gets: the capability, its flow, and where it was asked.
@immutable
class KitEnableRequest {
  const KitEnableRequest({required this.capability, required this.flow, this.host, this.serverName, this.source});
  final String capability;
  final String flow;
  final KitHost? host;        // the current server's host kind, when known
  final String? serverName;
  final String? source;       // the page id the offer was on
}

typedef KitEnableFlowHandler = Future<void> Function(BuildContext context, KitEnableRequest request);

abstract final class KitCapabilities {
  /// Every matrix capability (33), 21 of them with an enableFlow.
  static const List<KitCapability> all = [/* … */];

  static KitCapability? byId(String id);

  /// Set by the app at start-up (coord-main). Replaces an earlier handler.
  static void registerFlow(String flow, KitEnableFlowHandler handler);

  /// The entry has an enableFlow and its handler is registered.
  static bool canEnable(String capability);

  /// Runs the flow's handler; a no-op returning false when none is registered.
  static Future<bool> enable(BuildContext context, String capability, {KitHost? host, String? serverName, String? source});

  /// For the coord-main acceptance test: flows with no handler.
  static Iterable<String> get unregisteredFlows;

  @visibleForTesting
  static void debugReset();
}

class KitCapabilityExplainer extends StatelessWidget {
  /// A dimmed row that says why and offers the enable flow (§2.5; the
  /// "KitCapabilityRow"): builds KitRow.unavailable(title, reason, enable).
  const KitCapabilityExplainer.row({
    super.key,
    required this.capability,
    this.host,                 // the current host: "Files aren't available on Codex"
    this.serverName,
    this.title,                // default: the registry title ("Files")
    this.source,
    this.rowKey,
  });

  /// A missing-capability state (§2.2): builds KitStateView.missing with
  /// the registry's title, why and enable action.
  const KitCapabilityExplainer.state({
    super.key,
    required this.capability,
    this.host,
    this.serverName,
    this.cost = const [],      // KitNotice.cost items (download size, time, battery…) from the caller
    this.prerequisite = false, // "finish X first" (STATE-13)
    this.size = KitStateSize.inline,
    this.source,
    this.stateKey,
  });

  /// A turn-on offer at the moment of need (AUTO-18, KIT-37): KitNotice.offer
  /// with the enable action and "Not now". After "Not now" the caller passes
  /// folded: true, which renders the quiet row instead.
  const KitCapabilityExplainer.offer({
    super.key,
    required this.capability,
    required VoidCallback this.onNotNow,
    this.folded = false,
    this.message,              // default: the registry's offer sentence
    this.host,
    this.serverName,
    this.source,
    this.offerKey,
  });

  // The words, for callers that compose (the top bar, a notification):
  static String titleOf(BuildContext context, String capability);
  static String whyOf(BuildContext context, String capability, {KitHost? host, String? serverName});
  static String? enableLabelOf(BuildContext context, String capability); // null = explains only
  static String hostsLineOf(BuildContext context, String capability);    // "Works on this phone and on computers with OpenCode 2"
  static String hostWord(BuildContext context, KitHost host);
}
```

Notes:

- **The kit imports no screens and no domain types.** `KitHost` is a kit-level enum. The caller maps its `ServerCapabilities` and host kind to it; the UI gates on capabilities and host kind, never on the flavour enum (ARCH-2).
- **The lookup happens here, not in KitStateView or KitRow.** Those two are lower tiers and do not import this file (C25 direction: CapabilityExplainer depends on Row-v2 and StateView-v2). This is how C20's "KitRow.unavailable and KitStateView.missing look it up by capability id" is realised.
- **Copy (kit ARB, COPY-3):** per capability, `kitCap<Id>Title`, `kitCap<Id>Why`, `kitCap<Id>Enable` (only with a flow) and `kitCap<Id>Offer` (only with a flow). Per host, `kitHost<Name>`. The joiners are `kitCapWorksOn` "Works {hosts}", `kitCapNotOnHost` "{feature} isn't available on {host}" and `kitCapNotNow` "Not now". `<Id>` is the camel-cased id without punctuation (`voice.model` → `VoiceModel`, `flag:sessionDiff` → `FlagSessionDiff`). Engine words never appear (COPY-11). Backend names (Codex, Paseo, OpenCode 2) appear only in host words, where the person is choosing where to go (COPY-12). No enable label or offer mentions the setup assistant (AUTO-20, P2 deferred).

## States

| Variant | States |
|---|---|
| `.row` | explains (no flow, or no handler registered): dimmed, with the why as the supporting line; offers-enable: the same plus a trailing tertiary enable action |
| `.state` | explains; offers-enable (primary = enable, with the cost line); prerequisite (asserts that an enable action resolves) |
| `.offer` | open (one sentence, the enable action, and "Not now"); folded (after "Not now": the quiet row) |
| any, while the handler runs | the enable action shows `working` for its own tap (KitAction.working) and no lasting status (STATE-7); the flow itself shows its progress on its own page |
| unknown capability id | an assert in debug. In release it renders nothing and reports once through `FlutterError.reportError`, which the app's diagnostics already capture (never a dead row) |

- Loading and empty do not apply: the registry is const.
- Error: a handler that throws leaves the explainer as it was, and the handler's page reports the failure. The kit catches the error so a tap never crashes.
- Disabled: an enable action is never shown disabled. With no handler, the variant becomes explains (STATE-8: hidden rather than disabled without a reason).
- KIT-12 doc comment: "States: explains, offers-enable, prerequisite, offer, folded, working".

## Tokens

It is composed of other parts, so there are no new tokens.

- **ThemeRoles:**
  - the dimmed row uses `text3` for the title and `text2` for the why (KitRow.unavailable's look);
  - the state and the offer use their parts' roles;
  - no `attention`: a missing capability is not "needs you" (LOOK-4).
- **KitText:** through the composed parts (`rowTitle`, `secondary`, `headline`/`title` in the state).
- **KitTokens:** through the composed parts.

## Adaptive

- **compact / medium:** the row is full width in its panel. The state is inline by default, or page when the whole screen is the missing feature. The offer sits where the feature would be (capabilities.json rule 1).
- **expanded / large:** the same parts, adapting as KitRow, KitStateView and KitNotice do. In twoPane, a missing feature's state fills the detail pane.
- **Pointer and keyboard:** the row's enable action and the state's primary are Tab-reachable, and Enter activates. `.offer` puts "Not now" after the enable action in Tab order. There are no shortcuts.

## Accessibility

- **Row:** "{title}, unavailable, {why}" with a button for the enable action ("Download voice model"). No part of the explanation lives only in a tooltip (STATE-8).
- **State:** the live region comes from KitStateView. The offer's live region comes from KitNotice (announced once when it appears).
- **Targets and reflow:** targets are 48 dp, and at 200 % text everything wraps (the composed parts).

## RTL

- Host words and server names are wrapped with `KitBidi.auto` inside the why line (COPY-30). Directional layout comes from the composed parts.
- Latin product names (OpenCode 2, Codex, Paseo) stay in Latin script in Arabic (COPY-24).

## Motion and haptics

- The composed parts' motion only: KitRow, KitStateView's entrance, and KitNotice's entrance. Folding the offer into the row uses `KitReveal` on `KitMotion.standard`, instant under reduced motion.
- **Haptics:** none.

## Data safety and honest state

- **Nothing vanishes silently:** where a host cannot do something, the explainer says which host can (capabilities.json rule 4; STATE-12). `hidden` stays only where the registry entry has no flow and the page has no place for a line, and G13 checks that against the map.
- **Cost first:** before any install or turn-on primary, `.state` and `.offer` show the caller's cost items (KIT-37). The registry does not guess sizes, because they come from the component registry at the call site.
- **One offer per screen:** a capability is offered by exactly one row or notice on a screen (capabilities.json rule 2). The part cannot see the whole screen, so G37 or the reviewer checks this.
- **Never nag:** "Not now" folds the offer to one quiet row (AUTO-18). Remembering that choice per capability per server (key `oc.capabilityOffer.<capability>.<profileId>`, DATA-4) belongs to the caller or its slice, not the kit.
- **No dead ends:** a prerequisite explainer must resolve an enable action (STATE-13). The enable action exists only when a handler is registered, so it never leads nowhere.
- **Handler failures stay contained:** the kit catches handler exceptions and reports them through `FlutterError.reportError`. The kit imports no service code.

## Tests required

In `test/kit/kit_capability_explainer_test.dart`:

1. **Registry parity:** the test reads `docs/ux-system/capabilities.json` (a docs file, read with `dart:io` in the test only). Every `enableFlows[].capability` has a `KitCapabilities` entry with a non-null `enableFlow` in `KitEnableFlows.all` (21, all distinct). Every matrix capability has an entry whose `supported` and `partly` sets equal the matrix statuses.
2. **Registration:** `registerFlow` followed by `canEnable` is true. Without a handler, `canEnable` is false, and `.row` and `.state` render the explains variant with no enable action.
3. **Enable:** tapping enable calls the handler once, with `KitEnableRequest(capability, flow, host, serverName, source)`. A throwing handler does not crash, and the explainer stays.
4. **Why wording:** `whyOf('flag:fileBrowsing+terminal', host: KitHost.codex)` names Codex and the hosts that can. It contains no engine words (a glossary check against the COPY-11 list).
5. **`.offer`:** "Not now" calls `onNotNow` once. `folded: true` renders the quiet row, not the notice.
6. **Prerequisite:** `.state(prerequisite: true)` for a capability with no flow, or no handler, asserts (STATE-13, G37).
7. **Unknown id:** it asserts in debug.
8. **Keyboard** (G14x, desktop): Tab reaches the enable action, and Enter runs it.
9. **Deferred P2:** no ARB value for a `kitCap…` key contains "assistant" (AUTO-20).
10. **Reduced motion:** the fold from offer to row settles after one `pump()` (G8).

## Open questions

Both are coordinator decisions (naming only; the API is unaffected), to be settled before wave 1:

- **Flow-id names:** the 21 ids above are new names. capabilities.json names flows only in prose, and map `whenMissing` values point at page ids such as `offers-enable:voice-model-setup-sheet`. If the coordinator prefers flow id = the target page id, only the `KitEnableFlows` constant values change, and the API is unaffected.
- **Matrix flags:** ids such as `flag:fileBrowsing+terminal` are used verbatim as keys. If the coordinator wants dotted ids (`flag.fileBrowsing`), the table and the parity test change together before wave 1.
