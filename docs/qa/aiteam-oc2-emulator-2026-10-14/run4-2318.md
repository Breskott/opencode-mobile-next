## Setup UX judgment

- Model rows: work and are clear. "Server default" vs named model is explained. Issues: the Planner row had been set before (state from earlier run), so the first-time path for Planner was not exercised; a role's detail sheet puts Model and Fallback model rows with identical layout, and my first tap set the Fallback by accident because the sheet layout differs between Worker (Model at y 845) and Checker (Model at y 992, extra read-only line). Rows reorder after save (the edited role moves), which is disorienting.
- Folder picker: good. Creating a new folder in one step is the right idea. But it creates a non-git folder, so every new folder hits the no-commits error on first Start planning.
- First commit: the button is excellent and fast, but the error is shown at the top of a long scrolled sheet, while the user is looking at the bottom Start planning button. Looks like nothing happens for 1 to 2 minutes (P1).
- Start planning button disabled reasons chain one at a time ("Choose Single lane...", then "Set a budget or choose No limit.") and the sheet shifts layout when the keyboard closes; mode and budget have no defaults, so a simple task needs 2 extra taps. Suggest defaults (Single lane, No limit).
- Seeded milestone: works. Spec header still says "Draft spec . 0 milestones" while the body already has one: minor mismatch.
- Goal text typo "hid" came from my script, not the app.
- Plain-word errors: all seen errors were plain ("The planner stopped...", "no commits yet"); Details was collapsed.
