# Astra — ideas from ECC for OpenCode Mobile and FactsBook (2026-10-12)

ECC’s strongest contribution is explicit scope, evidence and trust boundaries around agent work. OpenCode Mobile can use these to strengthen execution; FactsBook can use them to strengthen proposals and review.

Read-only review of ECC `d4a44de` and the requested product documents. No files changed, installations performed or project code/tests executed. Effort: **S** = focused change; **M** = several components; **L** = substantial implementation and qualification. Slice names below are recommendations, not new commitments.

**1. What ECC is — five lines**

1. An MIT-licensed engineering workflow system, strongest on Claude Code, with adapters of differing capability.
2. Its central loop is plan → test → implement → review → verify → remember → improve.
3. It provides 71 agent definitions, 311 skills and 97 legacy command shims; these are instructions, not independent security boundaries.
4. Executable hooks and utilities add checks, context selection, persistence, learning and orchestration support.
5. AgentShield scanning is integrated through an external package; this checkout does not establish that scanner’s implementation or effectiveness.

Architecture, evidenced by [README.md](ECC/README.md):

- **Instructions:** `agents/`, canonical `skills/`, selective `rules/`, legacy `commands/`.
- **Execution:** `hooks/hooks.json`, `scripts/hooks/`, orchestration utilities and pilot `workflows/`.
- **State:** scoped memory vault, session summaries, observations and learned “instincts”.
- **Portability:** capability-specific harness adapters; support and hook activation differ.
- **Assurance:** schemas, tests, evaluation utilities and external security-scan integration.

**2. OpenCode Mobile — strengthen the existing product**

The current [README](oc_app/README.md) already documents planning, workers, checking, budgets and merge receipts. These recommendations extend that system; they do not assume it is missing.

- **ADOPT — explicit task contracts.** ECC’s [skills/team-agent-orchestration/SKILL.md](ECC/skills/team-agent-orchestration/SKILL.md) requires owner, scope, acceptance criteria, evidence and merge gate. Map these into existing AI Team task conversations, Details and `lib/orchestration/`. Show “what remains before merge” beside each task. **Value:** accountable workers and understandable blockers. **M**.

- **ADOPT — verification bound to the exact candidate.** [scripts/lib/eval-harness/receipt.js](ECC/scripts/lib/eval-harness/receipt.js) binds artifact and gate digests and detects stale checkpoints. Extend checker/merge cards with commit identity, check environment and passed/failed/skipped results; invalidate relevant evidence after changes. **Value:** yesterday’s passing tests cannot approve today’s diff. **M**.

- **ADOPT — truthful adapter capabilities.** [scripts/lib/harness-capabilities.js](ECC/scripts/lib/harness-capabilities.js) distinguishes native support, opt-in hooks and unavailable features. Apply this to gateway capability contracts, agent setup and permission cards: supported, enabled and qualified are separate states. **Value:** consistent screens without pretending Claude Code, Codex, Pi and OpenCode enforce identical controls. **M**.

- **ADAPT — bounded composer suggestions.** [scripts/hooks/context-prompt-suggestions.js](ECC/scripts/hooks/context-prompt-suggestions.js) supplies a small advisory suggestion set without granting permissions. Map to phrase chips and proposed Tidy/@files: preview rewritten text, selected files and destination; let users remove each addition. **Value:** fewer taps with visible context disclosure. **M**.

- **ADAPT — compact, source-linked handoffs.** [skills/unified-memory/SKILL.md](ECC/skills/unified-memory/SKILL.md) separates intent, attempts, verified results and remaining work. Use this for worker handoffs, interrupted chats and “Since you were away”: preserve branch, constraints, pending approvals and evidence links. **Value:** reliable continuation across agents and Android process death. **M**.

- **ADAPT — bounded loops under Android scheduling.** [skills/continuous-agent-loop/SKILL.md](ECC/skills/continuous-agent-loop/SKILL.md) identifies repeated failures, cost drift and stalled merges. Translate this into durable retry budgets and explicit stop reasons in Inbox; use typed engine events, checkpoints and existing work leases. **Value:** less battery/cost churn and recoverable suspension. **L** for runtime integration and qualification.

- **ADAPT — local preference learning.** [skills/continuous-learning-v2/SKILL.md](ECC/skills/continuous-learning-v2/SKILL.md) records evidence and project scope. Borrow those fields for phrase-chip preferences, with edit/hide/delete controls and explicit scope. **Value:** useful personalization without silently carrying one project’s instructions into another. **S–M**.

- **AVOID — wholesale catalogue and desktop automation import.** [skills/autonomous-loops/SKILL.md](ECC/skills/autonomous-loops/SKILL.md) includes process pipelines and indefinite-loop patterns. Keep a few role presets and sessions on the existing engine; do not launch a desktop-style observer/process fleet on the phone. **Value:** lower resource use and simpler configuration. **S** policy.

- **AVOID — generic checks becoming a “safe” badge.** [skills/verification-loop/SKILL.md](ECC/skills/verification-loop/SKILL.md) illustrates coverage thresholds, secret greps and periodic verification. Use project-owned checks and critical invariant tests instead of copying its commands or cadence. Map to checker configuration and merge readiness. **Value:** meaningful evidence without irrelevant work or false assurance. **S**.

**3. FactsBook — borrow contracts, preserve person-memory authority**

[D36–D37](factsbook/docs/00-decisions.md) govern roles and email-first ingestion. The current [B7 review](factsbook/docs/review/astra-b7-review-2026-10-12.md) reports two high admission findings and explicitly withholds core acceptance. Its corrective **B8** comes before provider or automatic-source activation.

- **ADOPT — recall is evidence, never permission.** [skills/unified-memory/SKILL.md](ECC/skills/unified-memory/SKILL.md) requires freshness checks, explicit supersession and untrusted recalled text. Strengthen **D25; specs 10/11/30** with source/date/status and visible corrections. A frequently recalled claim must not become more authoritative merely through repetition. **Value:** understandable, correctable personal memory. **S**.

- **ADOPT — incomplete is different from absent.** [tests/lib/memory-read-completeness.test.js](ECC/tests/lib/memory-read-completeness.test.js) covers interrupted and invalid scans. Apply to **specs 11/24**: locked areas, rebuilding indexes and unreadable records must not yield “you never told me”. Return appropriately scoped diagnostics without revealing inaccessible areas. **Value:** honest search and fewer harmful omissions. **M**.

- **ADAPT — small, versioned job contracts.** ECC’s [agents/architect.md](ECC/agents/architect.md) separates role, tools and model metadata. Under **D36; specs 32/33/60**, give extractor, gardener, scout and other roles their own input/output schemas, allowed tools, areas, budget and locality requirements. Enforce these in the node; retain owner-selected adapter or **none**. **Value:** narrower disclosure and easier qualification. **M**.

- **ADAPT — evaluate the whole email pipeline.** [tests/lib/context-profile-eval.test.js](ECC/tests/lib/context-profile-eval.test.js) pins evaluation inputs and retains failed attempts. Apply to **D37; spec 32 §6; spec 40**: test minimization → Jev header/snippet triage → selected-role extraction → review. Measure missed important mail, sensitive misrouting, unsupported proposals and review burden. **Value:** useful email assistance with measurable failure boundaries. **M**.

- **ADAPT — exact approval snapshots and durable claims.** [skills/operator-approval-loop/SKILL.md](ECC/skills/operator-approval-loop/SKILL.md) binds approval to text, destination and revision, then blocks retries after unknown delivery. Apply the pattern to **D13/D23; spec 42 and review preconditions**, retaining FactsBook’s signed owner authority. Reject its optional timeout auto-approval and unavailable-baseline permissiveness. **Value:** no stale approvals or accidental duplicate outward actions. **M**; sending remains later.

- **ADAPT — minimal job evidence receipts.** [scripts/lib/eval-harness/receipt.js](ECC/scripts/lib/eval-harness/receipt.js) provides useful digest and verification patterns. Under **specs 32/33 and the signed-operation contract**, retain model/template/schema/policy revisions, source references, validation outcome and budget usage. **Value:** traceable proposals and reproducible failures. **M**. Preserve existing signatures; neither hashes nor signatures prove a fact true.

- **AVOID — confidence-driven promotion into facts.** [skills/continuous-learning-v2/SKILL.md](ECC/skills/continuous-learning-v2/SKILL.md) allows stronger instincts and wider scope after repeated observations. For **D23/D25/D26; spec 30**, pattern discovery may create sourced review proposals only. Silence is not consent; repeated copies are not independent corroboration. **Value:** preserves review-first gardening and area boundaries. **S** for explicit invariants/tests.

- **AVOID — replacing FactsBook with ECC’s vault or observer.** [schemas/memory.schema.json](ECC/schemas/memory.schema.json) models unreviewed engineering context; [observe.sh](ECC/skills/continuous-learning-v2/hooks/observe.sh) captures tool content. Neither supplies FactsBook’s person entities, signed history, sensitive-area rules or approved writes. Preserve **D24/D34/D37; specs 10/21/33/50** and node-mediated changes. **Value:** one authoritative memory system without background personal-data collection. **S** architectural exclusion.

**4. Security and privacy lessons for both**

- **Inventory background egress, not just chat sends.** ECC’s observer defaults off, but [scripts/lib/llm-summary.js](ECC/scripts/lib/llm-summary.js) separately sends transcript excerpts through authenticated Claude for lifecycle summaries. Truncation is not redaction. OpenCode should disclose such destinations and payload categories; FactsBook must prevent sensitive content entering any hosted summarizer.

- **Make capability consent concrete.** [scripts/lib/install/hook-consent.js](ECC/scripts/lib/install/hook-consent.js) names source writes, process control, LLM egress, MCP activity and retained records. Borrow this vocabulary for agent/source setup, with enforceable per-job grants. D37’s Gmail read-only scope prevents mailbox changes; it does not prevent model disclosure. Sender, subject and snippet also require on-phone minimization and sensitivity checks.

- **Treat repositories, mail and memory as untrusted data.** ECC’s agent prompts contain defensive instructions; [hooks/README.md](ECC/hooks/README.md) also disables tracked Hookify rules by default. Both products need executor-enforced tool/data scope. A mail instruction or recalled preference must never authorize a send, broaden permissions or select another provider.

- **Borrow scanner coverage, not unverified guarantees.** [skills/security-scan/SKILL.md](ECC/skills/security-scan/SKILL.md) inventories instructions, hooks, MCP configuration, permissions and secrets, but invokes external AgentShield and offers API-backed deep analysis. Review its actual implementation and egress before integration. Keep Jev credentials in device Keystore; do not copy ECC’s environment-variable examples into FactsBook credential handling.

- **Pin and inspect executable dependencies.** [skills/mcp-dependency-review/SKILL.md](ECC/skills/mcp-dependency-review/SKILL.md) recommends static inspection, while some examples still use unpinned packages. Use reviewed versions, artifact digests, deliberate updates and narrow capabilities. Preserve ECC’s MIT notice when copying substantial code.

- **Keep containment claims honest.** [docs/architecture/eval-harness-frameworks.md](ECC/docs/architecture/eval-harness-frameworks.md) explicitly says candidate execution is unavailable without qualified OS containment. Effect labels, prompts and JavaScript wrappers are not sandboxes. Preserve OpenCode’s execution boundary and FactsBook’s separate proposal/validation/commit authority.

**5. Tests and evaluations worth borrowing**

- **Tamper, truncation and stale evidence:** [tests/lib/eval-harness/receipt.test.js](ECC/tests/lib/eval-harness/receipt.test.js). Apply to AI Team candidate receipts and FactsBook signed history, including changed artifacts and wrong keys.
- **Replay without real effects:** [tests/lib/eval-harness/replay.test.js](ECC/tests/lib/eval-harness/replay.test.js). Missing/corrupt fixtures must fail; replay must never call real sends, providers or publication tools.
- **Approval races and uncertain delivery:** [tests/skills/test_approval_delivery_claims.py](ECC/tests/skills/test_approval_delivery_claims.py). Test concurrent workers, changed destinations, stale revisions and crashes after dispatch.
- **Consent across alternate activation paths:** [tests/lib/opencode-hook-consent-safety.test.js](ECC/tests/lib/opencode-hook-consent-safety.test.js). A declined plugin must stay inactive even when another discovery mechanism finds it.
- **Secrets across the entire retention path:** [tests/hooks/observe-secret-redaction.test.js](ECC/tests/hooks/observe-secret-redaction.test.js). Extend with B7’s multiline/dangling-escape and repeated-request cases; inspect queues, history, exports and restored state for individual secret fragments.
- **Outcome benchmarks:** [skills/eval-harness/SKILL.md](ECC/skills/eval-harness/SKILL.md) distinguishes first-attempt success, success within retries and repeatability. Pin model/prompt/corpus, retain timeouts in denominators, and measure cost/latency. Add Arabic/English, interruption and adversarial cases. Safety violations cannot be averaged away by a high overall score.

These are source-reviewed patterns, not tests run during this study. ECC’s receipt/replay utilities are useful building blocks; its disabled candidate runner is not a ready-made evaluation sandbox.

**6. Ranked recommendations**

OpenCode Mobile:

1. **Exact-candidate verification receipts** — AI Team checker/merge evidence slice; **M**.
2. **Owner, scope, acceptance and merge conditions per task** — existing AI Team conversation/Details slice; **M**.
3. **Accurate capability and enforcement status per adapter** — gateway/setup qualification slice; **M**.
4. **Visible, removable context suggestions and Tidy previews** — composer/@files slice; **M**.
5. **Durable retry limits, stop reasons and checkpoints** — AI Team recovery/Android lifecycle slice; **L**.
6. **Source-linked handoffs with scoped local preferences** — context/resume and phrase-chip follow-up; **M**.

FactsBook:

1. **Close admission defects with retained-copy and restore regressions** — corrective **B8**, before enabling providers; **M**.
2. **Preserve provenance and distinguish incomplete recall from absence** — v1 search/review hardening; **M**.
3. **Enforce narrow, owner-selected role contracts and qualify Jev** — **D36**, after core acceptance; **M**.
4. **Implement minimized, capped, review-only email ingestion** — **D37 email-first**, retaining credential/egress gates; **L**.
5. **Pin whole-pipeline evaluations and retain minimal job evidence** — D36/D37 qualification plus memory care; **M**.
6. **Bind signed approval to exact payload/destination and reconcile unknown outcomes** — later **spec 42 outward-action slice**; **M**.
